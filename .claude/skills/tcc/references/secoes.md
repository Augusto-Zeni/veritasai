# Guia Detalhado de Seções — TCC I Univates 2026 (Modelo Produto)

---

## RESUMO / ABSTRACT

**Extensão:** 150–250 palavras cada.

**Estrutura do parágrafo único:**
1. Contexto e problema resolvido pelo produto (1–2 frases)
2. Público-alvo e relevância (1 frase)
3. Abordagem/metodologia adotada (1–2 frases)
4. Resultados esperados ou já obtidos (2–3 frases)
5. Contribuição/impacto do produto (1 frase)

**Palavras-chave:** 3 a 5 termos, separados por ponto, logo abaixo do resumo.

**ABNT (NBR 6028):** Espaçamento simples, sem recuo de parágrafo, justificado.
Título "RESUMO" centralizado, em negrito e maiúsculas. Sem citações.

---

## CAPÍTULO 1 — CONTEXTUALIZAÇÃO (2–3 páginas no total)

O capítulo 1 apresenta o produto, sua justificativa e delimita o escopo do trabalho.

### Corpo principal da contextualização

**O que escrever (2–3 páginas combinadas com as subseções):**
- Apresentar o produto ou serviço proposto e o problema que ele resolve
- Motivação do aluno: por que esse produto é interessante e relevante?
- Benefícios para a sociedade ou para o público-alvo consumidor
- Demonstração de que há **demanda real** pelo produto (dados, pesquisas, tendências de mercado)
- Por que agora? Qual o contexto atual que torna esse produto oportuno?

**Embasar afirmações com fontes:** estatísticas, relatórios de mercado, artigos, notícias
relevantes. Evitar afirmações sem respaldo ("todo mundo precisa de X").

---

### 1.1 Aplicação do produto e público-alvo (até 1 página)

**O que escrever:**
- Descrever claramente o problema principal que o produto resolve
- Definir quem é o **público-alvo / potencial consumidor**:
  - Perfil demográfico (idade, profissão, localização, renda)
  - Comportamento e necessidades
  - Tamanho estimado do mercado
- Como o produto se aplica ao dia a dia desse público?

**Dica:** Quanto mais específico o público-alvo, mais convincente fica o argumento de viabilidade.

---

### 1.2 Objetivos (~meia página)

**Objetivo Geral:** 1 único objetivo amplo, formulado com verbo no infinitivo.
- Exemplos de verbos: desenvolver, criar, implementar, propor, validar, analisar
- Deve ser atingível dentro do escopo do TCC
- Deve expressar o produto ou resultado final esperado

**Objetivos Específicos:** 3–5 objetivos, cada um com verbo no infinitivo.
> ⚠️ **ATENÇÃO:** Objetivos específicos NÃO são atividades ou tarefas executadas
> (ex.: "instalar o ambiente", "criar banco de dados", "fazer testes").
> São **ações de pesquisa/desenvolvimento** que contribuem para o objetivo geral
> (ex.: "identificar os requisitos principais do produto", "avaliar tecnologias disponíveis
> para X", "validar a aceitação do produto com o público-alvo").

---

### 1.3 Estrutura do trabalho (~meia página)

**O que escrever:**
Descrever brevemente o que será apresentado em cada capítulo subsequente.

Exemplo de formato:
> "Este trabalho está organizado em cinco capítulos. O Capítulo 2 apresenta o estudo do
> domínio do problema [...]. O Capítulo 3 traz o estudo de viabilidade e produtos similares
> [...]. O Capítulo 4 descreve o produto proposto e sua arquitetura técnica [...].
> Por fim, o Capítulo 5 apresenta as considerações finais e o cronograma [...]."

## CAPÍTULO 2 — ESTUDO DO DOMÍNIO DO PROBLEMA

**O que é:** Estudo teórico que demonstra compreensão profunda da área/problema para o qual
se pretende criar a solução. O foco deve estar no **problema**, não na tecnologia.

> ⚠️ **Regra da Univates:** NÃO abordar conceitos que não sejam diretamente relacionados
> ao problema. NÃO definir tecnologias, linguagens de programação ou frameworks — isso vai
> no Capítulo 4.

**Exemplo prático da Univates:**
Se o produto for um sistema de reconhecimento de glaucoma em imagens de fundo de olho:
- O que é glaucoma? Características, causas, progressão
- Por que o diagnóstico precoce é importante?
- Como o diagnóstico é feito tradicionalmente? Limitações do processo atual
- Que ganho um sistema automatizado de reconhecimento de padrões traria para a saúde?
- Dados epidemiológicos e impacto social

**Estrutura:** Organize em subseções temáticas, cada uma com embasamento científico.
Todas as afirmações devem ter citações de autores que as sustentam.
Use fontes primárias: artigos científicos, livros técnicos, relatórios de entidades reconhecidas.

## CAPÍTULO 3 — ESTUDO DE VIABILIDADE E PRODUTOS SIMILARES

**O que é:** Análise de mercado e apresentação de produtos/trabalhos similares, com tom de
**pitch para investidores** — o texto deve convencer o leitor de que vale a pena investir
tempo, pesquisa e recursos no desenvolvimento deste produto.

### 3.1 Produtos e trabalhos similares

**O que escrever:**
- Apresentar o máximo possível de produtos similares já disponíveis no mercado
- Apresentar trabalhos acadêmicos relacionados ao objetivo do TCC
- Para cada similar: descrever funcionalidades, pontos fortes, pontos fracos, público atendido
- Comparar com o produto proposto: o que este TCC faz diferente ou melhor?

**Formato sugerido — tabela comparativa:**

| Produto/Trabalho | Funcionalidades | Pontos Fortes | Limitações | Diferencial deste TCC |
|---|---|---|---|---|
| Nome (ano) | ... | ... | ... | ... |

---

### 3.2 Viabilidade financeira

O texto deve responder às seguintes questões (não precisam ser uma a uma, mas todas devem
estar presentes no texto):

- **Existe clientela?** Comprovada por pesquisa de mercado ou dados de demanda
- **Quem são os potenciais clientes?** Perfil e estimativa de volume
- **Custo de desenvolvimento e produção** — estimativa
- **Valor de comercialização** — como será precificado?
- **Margem de lucro esperada**
- **Tempo estimado de retorno do investimento (payback)**
- **Os clientes têm recursos para pagar pelo produto?**
- **Modelo de monetização:** assinatura, licença, freemium, venda direta, marketplace...
- **Novas funcionalidades futuras** que podem aumentar a receita
- **Como o produto chegará ao mercado?** Canais de distribuição, estratégia de lançamento
- **Custo de aquisição de clientes (CAC)** e investimento em publicidade
- **Ponto de equilíbrio (break-even):** quando as receitas cobrem as despesas?
- **Possíveis parceiros estratégicos ou canais de distribuição**

---

### 3.3 Viabilidade técnica

**O que escrever:**
- As tecnologias necessárias estão disponíveis e acessíveis?
- É tecnicamente possível desenvolver o produto com a equipe e os recursos disponíveis?
- A qualidade mínima para satisfazer o cliente pode ser alcançada?
- O custo técnico é compatível com o preço que o cliente pode pagar?
- Existem riscos técnicos relevantes? Como serão mitigados?

**Objetivo:** Deixar claro que é possível construir o produto, que as tecnologias existem
e que a solução técnica produzirá resultado satisfatório a um custo viável.

---

## CAPÍTULO 4 — DESCRIÇÃO DO PRODUTO PROPOSTO

**O que é:** Visão técnica completa do produto a ser desenvolvido. Não é necessário ter a
solução pronta, mas é **obrigatório construir uma versão inicial** (protótipo/MVP) para
validar a viabilidade técnica.

**Subseções sugeridas (o aluno pode adaptar conforme necessidade):**

### 4.1 Arquitetura da solução proposta

- Diagrama de arquitetura do sistema
- Componentes principais e como se integram
- Tecnologias escolhidas e como serão empregadas/integradas ao produto
- Justificativa para as escolhas tecnológicas

### 4.2 Requisitos e casos de uso

- Requisitos funcionais (o que o sistema deve fazer)
- Requisitos não funcionais (desempenho, segurança, usabilidade, escalabilidade)
- Casos de uso principais ou histórias de usuário
- Modelo de dados (diagrama ER ou esquema, se aplicável)

### 4.3 Proposta de validação do produto

- Como a versão inicial será testada?
- Critérios de sucesso da validação
- Métricas que indicarão se o produto resolve o problema
- Planejamento para coleta de feedback do público-alvo

### 4.4 Versão inicial desenvolvida

- Descrever todas as etapas do desenvolvimento da versão inicial (MVP/protótipo)
- O que foi implementado e por que
- Evidências de funcionamento: capturas de tela, fluxos, demonstrações
- Lições aprendidas e ajustes realizados

> ⚠️ **Figuras e tabelas (ABNT):**
> - Numeração sequencial: Figura 1, Figura 2... / Tabela 1, Tabela 2...
> - Título **acima** da tabela e **abaixo** da figura
> - Fonte logo abaixo (mesmo que seja do autor: "Fonte: elaborado pelo autor")
> - Toda figura/tabela deve ser citada no texto antes de aparecer

## CAPÍTULO 5 — CONSIDERAÇÕES FINAIS

**O que é:** Reflexão sobre o trabalho realizado até o momento, resultados esperados
e desafios identificados.

**Estrutura:**

1. **Resultados esperados** (1–2 parágrafos)
   - Quais são os resultados previstos para o produto completo?
   - Esses resultados são suficientes para resolver o problema identificado? Justificar.

2. **Resultados preliminares já obtidos** (1–2 parágrafos)
   - O que já foi desenvolvido, testado ou validado com a versão inicial?
   - Incluir evidências concretas (dados de testes, feedback de usuários, métricas)

3. **Dificuldades e riscos** (1 parágrafo)
   - Quais dificuldades foram encontradas até agora?
   - Quais desafios ou riscos podem ameaçar o sucesso do produto?
   - Como pretende mitigá-los?

> ⚠️ Tom: honesto e reflexivo. Citar dificuldades reais não prejudica o trabalho —
> ao contrário, demonstra maturidade e consciência sobre o projeto.

---

### 5.1 Cronograma

**O que escrever:**
- Cronograma completo do TCC, incluindo etapas **já concluídas** e **próximas etapas**
- Considerar obrigatoriamente:
  - Seminário de Andamento
  - Tempo para revisão pelo orientador e incorporação de correções
  - Data de entrega do TCC
  - Datas das bancas previstas no calendário da Univates

**Formato — tabela por quinzena ou mês:**

| Atividade | Jan/Q1 | Jan/Q2 | Fev/Q1 | Fev/Q2 | Mar/Q1 | ... |
|---|---|---|---|---|---|---|
| Desenvolvimento módulo X | ✓ | ✓ | | | | |
| Testes com usuários | | | ✓ | ✓ | | |
| Ajustes pós-feedback | | | | | ✓ | |
| Escrita dos resultados | | | | | ✓ | |
| Revisão pelo orientador | | | | | | |
| Entrega final | | | | | | |
| Banca | | | | | | |

**Dica:** Ser realista com os prazos. Subestimar o tempo de desenvolvimento é o erro
mais comum. Sempre incluir margem para imprevistos.
