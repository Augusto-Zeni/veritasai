# Diário de desenvolvimento

Registro de decisões, alternativas testadas e problemas encontrados (alimenta o Capítulo 4 do TCC).

| Data       | Decisão / ocorrência                                                                                                                                                                                                | Motivo                                                                                                                                                                                                     |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 2026-11-17 | Monorepo com pnpm workspaces: `packages/core`, `apps/api`, `apps/web`, `eval`.                                                                                                                                      | Separar o pipeline puro (reutilizado pela API e pela avaliação) das interfaces.                                                                                                                            |
| 2026-11-17 | `@veritasai/core` como pacote interno sem etapa de build (`exports` → `src/index.ts`), executado com `tsx` (API/avaliação) e Vite (web).                                                                            | Menos configuração e nenhum artefato compilado para manter em sincronia.                                                                                                                                   |
| 2026-11-17 | TypeScript fixado em 6.0 em vez do 7.0 (versão `latest`).                                                                                                                                                           | O `typescript-eslint` ainda não suporta o TS 7 (compilador nativo); manter lint com regras tipadas pesa mais que o ganho de velocidade.                                                                    |
| 2026-11-17 | Ambiente local em Node 26; projeto declara `engines: >=24` e `.nvmrc` = 24.                                                                                                                                         | Node 24 LTS é a referência citada no texto; o código não depende de recursos exclusivos do 26.                                                                                                             |
| 2026-11-17 | pnpm instalado via `npm i -g pnpm@10`.                                                                                                                                                                              | O Corepack deixou de vir junto com o Node a partir da versão 25.                                                                                                                                           |
| 2026-11-17 | Tipos de domínio definidos como schemas Zod (tipos inferidos com `z.infer`).                                                                                                                                        | Uma única definição serve para validar saídas de LLM, o cache e o `results.jsonl`, e para tipar o código.                                                                                                  |
| 2026-11-17 | Scoring: com N = 0 ou só INSUFICIENTE, `score = null`, `coverage = 0` e veredito IMPRECISO; comparação com os limiares usa tolerância de 1e-9.                                                                      | A fórmula não define s quando n_s + n_c = 0; a tolerância evita que erro de ponto flutuante jogue casos de fronteira (ex.: 3/10 = 0,3) para o lado errado.                                                 |
| 2026-11-17 | `EXCLUDE_FACTCHECK_DOMAINS` lido como enum `true/false/1/0`, não com `z.coerce.boolean`.                                                                                                                            | `z.coerce.boolean('false')` resulta em `true`, o que ligaria a exclusão sem querer.                                                                                                                        |
| 2026-11-17 | Clientes externos atrás de interfaces (`LlmClient`, `SearchClient`, `ReaderClient`) com dependências injetadas (`fetch`, SDK, relógio, `sleep`).                                                                    | Permite testar tudo com respostas gravadas, sem rede e sem gastar cota.                                                                                                                                    |
| 2026-11-17 | A tabela `llm_cache` também guarda respostas do Serper, do Jina e do Readability (coluna `model` = `serper`, `jina`, `readability`).                                                                                | Reprodutibilidade da avaliação exige congelar também as buscas e as páginas lidas; evita criar tabelas além das duas previstas.                                                                            |
| 2026-11-17 | Cache do Serper guarda os resultados brutos, antes da exclusão de domínios.                                                                                                                                         | As variantes `full` e `full-no-factcheck-domains` reaproveitam a mesma busca, e a única diferença entre elas passa a ser a exclusão.                                                                       |
| 2026-11-17 | Exclusão de domínios feita filtrando os resultados (10 por consulta), e não com `-site:` na consulta.                                                                                                               | Algumas agências são seções de portais (`estadao.com.br/estadao-verifica`, `g1.globo.com/fato-ou-fake`), que o operador `-site:` não separa do resto do portal.                                            |
| 2026-11-17 | Respostas inválidas do LLM (JSON quebrado ou fora do schema) não são guardadas no cache.                                                                                                                            | Senão uma falha ocasional ficaria "congelada" e se repetiria em toda nova execução.                                                                                                                        |
| 2026-11-17 | Gemini: `temperature: 0` e `seed: 42` fixos; tokens de raciocínio (`thoughtsTokenCount`) somados aos de saída.                                                                                                      | O Gemini não garante determinismo nem com temperatura 0; a seed reduz a variação. Os modelos Flash atuais "pensam" por padrão e esses tokens também são cobrados.                                          |
| 2026-11-17 | 429 do Gemini com cota diária esgotada (`PerDay`) não é repetido; 429 por minuto é repetido respeitando o `retryDelay` informado pela API.                                                                          | Repetir quando a cota do dia acabou só desperdiça tempo.                                                                                                                                                   |
| 2026-11-17 | O limite `LLM_RPD` é contado só dentro do processo (janela de 24 h).                                                                                                                                                | Simplicidade; a cota real do Google é controlada pelo próprio Google e o 429 diário é tratado.                                                                                                             |
| 2026-11-17 | Seleção de trechos de evidência por ranking lexical BM25 (sem LLM), com IDF calculado sobre os trechos de todas as páginas da afirmação. Trecho só é aceito se contiver ≥ 2 termos distintos da afirmação (ou 25%). | Com LLM, seriam até 3 chamadas extras por afirmação (~30 por notícia), inviável com `LLM_RPD` na casa de 100. BM25 é determinístico e reprodutível. Alternativa a testar depois: reranking por embeddings. |
| 2026-11-17 | QueryGeneration gera as consultas de todas as afirmações numa única chamada ao LLM; se falhar, usa o texto da própria afirmação como consulta.                                                                      | Reduz de N para 1 chamada por notícia. Orçamento estimado: ~12 chamadas/notícia (1 extração + 1 consultas + até 10 verificações).                                                                          |
| 2026-11-17 | Verification não chama o LLM quando não há evidências (rótulo INSUFICIENTE direto).                                                                                                                                 | Economia de cota, e o resultado seria o mesmo.                                                                                                                                                             |
| 2026-11-17 | Página de evidência que não pode ser lida (paywall, bloqueio) é substituída pelo snippet do buscador, se este passar no mesmo filtro de relevância.                                                                 | Muitos portais bloqueiam leitura automatizada; o snippet do Google costuma conter o trecho relevante.                                                                                                      |
| 2026-11-17 | Evidências recebem ids (E1, E2...) e a verificação devolve `evidenceIdsUsed`; ids que o LLM inventar são descartados.                                                                                               | Transparência: cada rótulo aponta as fontes que o sustentam.                                                                                                                                               |
| 2026-11-17 | Prompts em `.md` (front-matter `id`/`version` + blocos `<system>`/`<user>`), excluídos do Prettier.                                                                                                                 | Qualquer mudança de texto precisa ser intencional e vir com nova versão; formatação automática alteraria o prompt sem trocar a versão.                                                                     |
| 2026-11-17 | Explicação do veredito gerada por modelo de texto a partir das contagens (sem LLM).                                                                                                                                 | A explicação nunca contradiz o veredito calculado e não gasta cota.                                                                                                                                        |
| 2026-11-17 | Afirmação que falha (cota, erro de rede, saída inválida) vira INSUFICIENTE com o motivo em `error` e em `meta.warnings`; falhas no scraping ou na extração de afirmações interrompem a verificação.                 | Degradação elegante sem esconder o problema; sem texto ou sem afirmações não há o que verificar.                                                                                                           |
| 2026-11-17 | Verificações com alguma afirmação em erro não vão para o cache de verificações.                                                                                                                                     | Erros costumam ser temporários (cota); cachear congelaria um resultado pior.                                                                                                                               |
| 2026-11-17 | Chave do cache de verificações = hash(modelo + versões dos prompts + config), ignorando campos operacionais (caminho do cache, RPM/RPD).                                                                            | Mudar prompt, modelo ou limiar invalida automaticamente os resultados antigos.                                                                                                                             |
| 2026-11-17 | Afirmações processadas com até 3 em paralelo; o LLM continua serializado pelo RateLimiter.                                                                                                                          | Busca e leitura de páginas são o gargalo de tempo e não têm o limite apertado do Gemini.                                                                                                                   |
| 2026-11-17 | Consumo por notícia calculado pela diferença entre dois snapshots do `UsageTracker`.                                                                                                                                | Os clientes são compartilhados entre execuções; exato em execuções sequenciais (CLI, avaliação). Na API, com verificações simultâneas, os números se misturam — limitação a tratar no passo 6.             |
